# 動画・音声から譜面を作る(vid2dtx の移植)

プレー動画に流れるチップを読んで譜面にする機能(vid2dtx の `detect` → `track` → `emit`、以下「動画から」)と、
曲の音からドラムの譜面の下書きを作る機能(vid2dtx の `audio2dtx`、以下「音から」)。ホームの「動画・音声から譜面を作る」から使う。
コードは `js/gen/`。移植元は vid2dtx の main(`14b2084`)の `vid2dtx/config.py`・`detect.py`・`track.py`・`emit.py`・
`avsync.py`・`audio2dtx.py`・`stemflux.py`。vid2dtx は作者のツールで、第三者のコードは入っていない。

このページは「元の挙動(値と式)」と「本アプリで変えた所(とその理由)」「移さなかった所(とその理由)」。
変えた所はコードのコメントに「(変更)」、元に無いものは「(追加)」と書いてある。

## 0. 何を移し、何を移さなかったか

| 元(vid2dtx) | 本アプリ | 理由 |
|---|---|---|
| 動画: OpenCV で全部のコマを読む(`detect.main`) | `<video>` を流し、`requestVideoFrameCallback` で出たコマを読む(`js/gen/frames.js`) | ブラウザで動画を復号する一般の手段。飛んだコマは無いだけで、残りのコマの時刻は正しい |
| 動画: 検出・追跡・格子・量子化・#BPM・小節長(`detect` / `track` / `emit`) | そのまま移した(`detect.js` / `track.js` / `emit.js`) | 学習を使わない計算なので、値も式も同じにできる |
| 音と絵のずれ(`avsync`) | 移した。時刻の付け方を 1 か所直した(§5) | |
| BGM を ffmpeg で `bgm.ogg` に切り出し、書き出した音で測り直して切り直す | 復号した音を標本の単位で切って `bgm.wav` にする。測り直しはしない | ブラウザに ogg の符号化器が無い。標本の単位で切れば切り直しは要らない |
| 既定キット(手元の曲パックの ogg を `#WAV` で指す) | 本アプリの合成音(`js/core/synth.js`)を `kit_*.wav` にして同梱 | 第三者の音は公開のリポジトリに置かない(CLAUDE.md)。書き出した ZIP は DTXMania でもそのまま鳴る |
| ドラム音キット(kitgen: 曲に似せる / 配布用(合成)) | 移さない | 学習した重み(`kitgen_*.pth`)と手元のライブラリの索引に頼る。「曲に似せる」の音は第三者の音そのもの |
| 音から: htdemucs・ADTOF・Beat This・MDX23C | 学習を使わない信号処理に置き換えた(§6) | モデルはブラウザで動かせず(数百 MB・PyTorch)、ライセンスもそれぞれ確かめが要る |
| 音から: 8 クラスのヘッド・奏法のイディオムのモデル(`adtof8_head_weights.pth`・`idiom_weights.pth`) | 移さない(重みが無いときの規則で動く) | GITADORA の譜面と音で学習した重みで、著作物から作ったものを公開できない |
| 評価(`evaluate.py`・`gitadora_bench.py`) | 移さない(手元で測った結果は §8) | 正解の譜面・曲は第三者のもの。テストは合成した動画と音で行う |

## 2. コマごとの検出(`detect.py` → `js/gen/detect.js`)

- 色は OpenCV の 8 bit の HSV(S = round(255·(max − min) / max)、V = max)。割り算を避けて `510·d ≥ (2T − 1)·V` などで比べる(同じ判定)
- レーンごとに、条件を満たす画素が帯の幅の `coreRowFrac` 以上の行を拾い、間が 2 行までの行を 1 つにまとめる(`group_rows`)。
  記録は (コマ, レーン, 行の中心 y, 行の数)
- 線は灰色の画素がフィールドの幅の `lineRowFrac` 以上の行。記録は (コマ, y, その行の灰色の画素の V の平均)
- 元が記録だけして使っていない色相・彩度の中央値は記録しない

## 3. 追跡(`track.py` → `js/gen/track.js`)

- 判定ラインを通る時刻 r = t + (judgeY − y) / v。r の並びに 28 ms より大きい間があれば塊を分ける。5 コマ以上に映り、y を t の直線で
  当てはめた傾きが v の ±20 %、外れの rms が max(6, 0.3·v / fps) 以下の塊だけを出来事にする(通る時刻は直線の判定ラインの所)
- 止まった検出(前後のコマの同じ y ± 3 px に検出があるもの)は除く。同じコマの近い行は重み(行の数)付きの平均でまとめる
- 速さ: 線(無ければチップ)の隣のコマとの差 1〜90 px を 0.5 px のヒストグラムに入れ、山の ±1.5 px の中央値 × fps。
  12 コマ以上の塊の傾きの中央値で 2 回詰める
- コマ落ち: 動くもの 3 つ以上の 8 割が 0 歩 / 2 歩でそろい、前後の見えたコマもきれいに動くときだけ 0 / 2 と数え、累計を中身の
  上のコマの番号にして塊を作り直す。0 歩が 3 コマ以上続くのは止まった画面(1 歩と数える)
- 丸めは numpy と同じ偶数への丸め(`js/gen/num.js` の `rint`)
- (追加)コマを間引いて読んだとき(読んだコマの番号の間の中央値 step > 1)は、速さの見積もりを step コマ離れたコマの組で行い、
  詰める塊の下限を ceil(12 / step) コマにし、コマ落ちの補正はしない(続いたコマが要る)
- (追加)コマの番号は rVFC の `mediaTime` から: 読んだコマの間の短い方の 1 割の値を 1〜4 で割った候補のうち、間の 98 % が
  その整数倍になる一番長いものをコマの間隔にし、番号を振って直線で当てはめ直す(59.94 fps も)。番号 0 の時刻(位相)は
  出来事の時刻に足す

## 4. 格子と量子化(`emit.py` → `js/gen/emit.js`)

- 線の出来事に半拍の格子 t = t0 + h·half を最小二乗で当てはめる。番号は隣との差を順に足して付け(`max(1, round(2·差 / 拍))`)、
  3 回当てはめ直す。BPM = 30 / half
- 小節の頭: 明るさの 20 % 点と 90 % 点の真ん中より明るい線。明るい線と暗い線の差が 10 未満なら多数決の位相だけ(全部 4/4)。
  明るい線は全部小節の頭(3/4・7/8 もそのまま)。4/4 がまるごと抜けた所は 4/4 で埋める
- 譜面の小節 0 = 動画の小節 0(最初の線以降で最初に始まる小節)を `measureOffset` 小節目にした所。既定は最初のチップが小節 1 に
  来るように。難易度ごとの動画で小節番号をそろえるときは同じ値を入れる(ダイアログの「最初の小節の番号」)
- (変更)最初のチップの小節を数えるとき、小節の頭の手前 6 tick(12 の格子の半分)までのチップはその小節のチップと数える。
  元は 1e-6 だけで、小節の頭のチップが 1〜2 ms 早く測れると前の小節のチップと数え、頭に空の小節が 1 つ増えた
  (吸着すると次の小節の 0 になるので、チップの位置は同じ)
- チップは小節の頭から 12(32 分)と 16(3 連)の倍数の格子に吸着。外れが max(5 ms, 4 × 全体の散らばり, 3 × そのチップの rms / 速さ)
  より大きいものは一番近い 1/384 に残す。位置は小節の 1/384 の整数(7/8 の小節も 384 の格子に丸めて書く)
- (追加)間引いて読んだときは 5 ms を 5 × step ms にする(2 倍速を 60 Hz の画面で読むと 2〜3 コマおきになり、絵空事で 3 個が
  格子の 2〜4 tick 外に置かれた)
- #BPM は整数 / 小数 2 桁のうち、曲の長さで 1 ms 未満しかずれないもの。だめなら小数 3 桁
- 小節長は変わる所ごとに `#mmm02`(4/4 に戻る所も書く)。チャンネルの行は tick の最大公約数で分割数を決める(`render_channel_line`)

## 5. 音と絵のずれ(`avsync.py` → `js/gen/avsync.js`)

- 動画の音を 22050 Hz・1 本にし、110 標本(5 ms)ごとの RMS の差の正の部分を標準偏差で割った包絡を作る。チップの時刻を ±200 ms
  の 5 ms 刻みでずらして包絡の平均を取り、峰 ÷ 中央値が 1.6 未満なら測れなかったことにする。峰の ±25 ms を 1 ms 刻みで見て、
  半分より上の山の重心をずれにする。正なら音が遅れている(BGM を後ろから切る)
- (変更)包絡の差 flux[i] は刻み i と i + 1 の間の立ち上がりなので、時刻 (i + 1)·hop で引く。元は i·hop で引くので 1 刻み早く出て、
  絵空事のプレー動画(元の譜面から分かる本当のずれ −0.8 ms)で −8 ms と測った(直したあとは −3 ms)
- BGM は「譜面の小節 0 の動画の時刻 + ずれ」から切る(負なら頭に無音を足す。元はその場合 BGM を書かない)。手で入れた値
  (ダイアログの「タイミング補正」)は測らずにそのまま使う(+ でチップが遅く聞こえる)

## 6. 音から(`audio2dtx.py` → `js/gen/adt.js`・`js/gen/audio2dtx.js`。実験的)

元の流れ: 分離(htdemucs)→ 採譜(ADTOF。既定と低いしきい値)→ 拍の追跡(Beat This)→ コムフィット → キットの分離(MDX23C)で
候補を裏付け → ドラマーの規則 → 出力。本アプリは打点を拾う所を信号処理に置き換え、そのあとを移した。

### 6.1 打点を拾う(追加。`adt.js`)

1. 44.1 kHz・2048 点・刻み 441(100 fps。ADTOF と同じ)の振幅のスペクトログラム
2. HPSS: 時間方向 17 コマ・周波数方向 17 bin の中央値のフィルタで、打楽器の側の柔らかいマスク P² / (H² + P²) を掛ける
3. 対数の帯域(9 bin までは 1 bin ずつ、上は 1/6 オクターブ)にまとめ、型(キック 60 Hz・スネア 200 Hz + 3 kHz・タム 130 Hz・
   金物 10 kHz の、対数の周波数のガウスの山)から始める NMF(KL の乗法の更新、40 回。はじめの 20 回は型を固定し、そのあと
   学んだ形へ 3 割寄せる)。型の外の成分は無し(付けると金物の成分を取られた)
4. キック・スネア: 成分の活性の峰のうち、相対の立ち上がり (a − 直前の底) / (直前の底 + c·尺度) が 1 以上のもの
   (キック c = 0.2・底は前 5 コマ、スネア c = 0.4・前 12 コマ。尺度は峰の高さの 95 % 点)。スネアはスネアの帯域(150〜8000 Hz)の
   立ち上がりの際立ち(`FluxEnv.bump` と同じ式)が 1 以上のものだけ(元の `VERIFY_Z` と同じ裏付け)
5. 金物: 7〜16 kHz の打楽器の側の立ち上がり(z)の峰が 2.5 以上で、際立ちがスネアの帯域の 0.3 倍以上のもの(スネアの漏れを除く)。
   250〜600 ms 後の一番低い所が打つ前の一番低い所の 1.2 倍より高く、打つ前からの上がりが 0〜80 ms の上がりの 0.05 倍以上なら
   シンバル、ほかはハイハット
6. 打点の時刻: 活性は峰の手前で底から峰までの半分を越えた所、立ち上がりは flux の峰。コマ i の時刻は i / 100 + 窓の 3/4
   (合成の打点で偏りが ±1.5 ms の内)
7. タムは拾わない(NMF の活性でも帯域でも、3 曲で適合率が 5 % ほどしか無かった)

### 6.2 テンポと小節(`fit_measure_grid` の移植と、拍の追跡の代わり)

- (追加)拍の候補: キック・スネアを 1、金物を 0.5 にした打点の並び(100 fps)の自己相関の 0.24〜1.0 s の峰に、BPM の対数の
  正規分布の重み(中心 150・幅 0.5 オクターブ)を掛けた上位 6 つ。候補ごとに下のコムを当て、キック・スネアの打点が格子に乗る
  割合 × 重みの平方根が一番大きいもの(自己相関だけだと絵空事の 200 BPM を 133 と取り違えた)
- コム(移植): 拍の候補の ±6 % を 3001 通り、16 分と 8 分 3 連(拍の 12 分の 0・3・4・6・8・9)の ±0.12 × 16 分の内に入る
  打点の割合で探し、前後を 201 通りで細かく探す。16 分の位相は直線の格子だけで決め、格子から 20 ms の内の打点で 3 回最小二乗
- (変更)小節の頭: 元は拍の追跡の小節の頭の多数決。本アプリはキック(1)・シンバル(2)・強さに比例した金物(0.5 × 強さ)の
  16 分の位置ごとの数。はっきりしたスネアのバックビート(8 分の位置 q と q + 8 の 16 分に 20 以上で、ほかの 3 倍以上、両方とも
  鳴る)があれば拍はそれで決め(q − 4 が 1 拍目か 3 拍目)、1 拍目と 3 拍目は上の数で選ぶ(移植)
- (追加)格子(16 分・8 分 3 連)から 16 分の 0.2 より外れた打点は曲のほかの音として捨てる
- BPM は一定、小節は 4/4(元と同じ)。#BPM は整数から 0.02 の内なら整数、ほかは小数 2 桁(元と同じ)

### 6.3 ドラマーの規則(`drummer_model` の重み無しの道の移植)

- 量子化は `emit.quantize`(12 / 16 の格子)。最初のチップが小節 1 に来るように小節を足す
- 32 分の 2 打目: 60 ms の内に次が無いスネアの 32 分あとに、スネアの帯域の際立ちが 1.5 以上あれば足す
- 1 つの tick の手(SD・TT・HH・CY)は 2 つまで。確信度の低い順、同じなら TT → CY → HH → SD の順に落とす
- ハイハットの開閉: 7〜16 kHz の余韻の比 ≥ 0.25 なら開。(変更)後ろの窓(100〜250 ms、次のハイハットの手前まで)は平均でなく
  一番低い所(分けた音でないので、次の打点の音を余韻と数えない)
- シンバルの左右: 2500 Hz の高域通過のあとの 60 ms の RMS の (R − L) / (R + L) が負なら LC
- グルーヴの型: 裏の 8 分の開いたハイハットが 2 つ以上の小節は、拍の頭にハイハットが無く高い帯域の際立ちが 0.5 以上なら、
  音が切れる(前後の比 < 0.6)なら LP、ほかは開のハイハットを確信度 0.35 で足す
- 速いキックの連打(間 140 ms 以下が 3 つ以上、2 つだけなら 90 ms 以下)は右足から交互に、1 つおきに LBD(左足が LP の所は右)
- タムの音高でのレーン分け(`split_tom_lanes`)はタムを拾わないので使わない
- 移さない(重みに頼る): ヘッドの HHC / HHO / LP・ライド・追加の候補、ハイハットとシンバルの同時打ちの裁き、イディオムの補完

### 6.4 確信度

- 元は採譜の活性の強さと相対の大きさ。本アプリは拾ったときの強さ: キックは相対の立ち上がり / 2、スネアは / 2.5、金物は z / 5
  (0〜1)。足したチップは 0.35。0.7 未満に編集画面が枠を付け、「次の要確認」で低い順に回る(`js/edit/sidecar.js`)
- ファイルは元と同じ形の `generated.dtx.conf.json`(`version`・`origin_s` = 元の音の時刻での小節 0・`t_meas`・`chips` の
  `m` / `tick` / `ch` / `conf` / `why`)

### 6.5 BGM

- 元: 元の音を小節 0 から切り出した `bgm.ogg`
- (変更)元のファイルが ogg / mp3 / wav なら、そのまま BGM にする(大きくならず音も変わらない)。曲の頭を小節 0 か 1 の中に置き、
  その位置を 1/384 小節に合わせて格子を 2 ms ほど動かす。ほかの形(m4a・動画など)は、小節 0 から切り出した `bgm.wav`

## 7. 書き出す曲フォルダと画面(`js/gen/generate.js`・`js/gen/dialog.js`)

- `<曲名>/generated.dtx`(Shift-JIS。書けない文字があれば UTF-8)・BGM・`kit_*.wav` 12 個・(音からは)確信度のファイル。
  曲名はダイアログで変えられる(既定はファイル名)。フォルダ名はファイル名に使えない文字を _ にしたもの
- できた ZIP は「編集画面で開く」で曲パックとして開き(ほかの ZIP を開くときと同じく、ファイルにしていない編集があれば確かめる)、
  その譜面を編集画面で開く。「ZIP を保存」でダウンロード。「前回の ZIP」にも残る
- 読む速さ: 等速(全部のコマ。コマ落ちの補正もする)/ 2 倍速(60 Hz の画面では 2〜3 コマおき)。読んでいる間にタブを隠すと
  動画も止める(rVFC が止まるので)。`requestVideoFrameCallback` の無いブラウザでは動画からは選べない
- 作っている間は進み具合を出し、「やめる」/ Esc でやめる。記録(vid2dtx の出力と同じ英語の行)は「記録」に出す
- ファイルはブラウザの中で読むだけで、どこにも送らない

## 9. 既知の限界

- 動画から: 対応する配置は §1 の 2 つ(とその拡大・縮小)。BPM・スクロールの速さが一定の譜面だけ(元と同じ)。
  ほかのスキン・ハイスピードの変化・演奏中のスクロールの止まりは読めない
- 音から: §8 の精度。テンポの変化と変拍子には対応しない(元と同じ)。打点は打ち始めより 10 ms ほど遅れて出ることがある
  (実曲の打点の立ち上がり)。小節の頭が半小節ずれたら、編集画面で頭に 2/4 の小節を足して直す
- 長い動画は音を丸ごと読むので、メモリを使う(10 分で数百 MB)
