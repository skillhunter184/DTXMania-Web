# 譜面の編集(本アプリの追加)

DTX 譜面を置く・消す・動かす・選ぶ・テンポと小節を変える画面。DTXMania NX 同梱の DTXCreator(以下 DTXC)と
vid2dtx のプレビュー(以下 V2D)を手本にした、本アプリの追加機能。手本の挙動は
[dtxcreator-edit.md](dtxcreator-edit.md)・[dtxcreator-ui.md](dtxcreator-ui.md)・[dtxcreator-io.md](dtxcreator-io.md)・
[vid2dtx-edit.md](vid2dtx-edit.md)。ここは「作ったものの挙動」と、手本と違えたところ(末尾の一覧)。

コードは `js/edit/`。文書(`dtxdoc.js`)→ モデル(`model.js`)→ 操作(`ops.js`)→ 履歴(`history.js`)→ セッション
(`session.js`。曲パックへの重ね合わせと下書き)→ 画面(`editor.js` / `view.js` / `gestures.js` / `dialogs.js`)。

## 1. 入口と出口

- 曲の一覧の「✎ 譜面を編集」を押してから譜面を選ぶ。演奏画面の ✎(ドラムのとき)は、今の位置・分岐(`#RANDOM` の乱数)・
  ループを持って開く
- ← で曲の一覧へ。確かめずに閉じる(編集は曲パックに重ね、下書きにも書く。ファイルにするのは「保存」)
- 編集の状態(元に戻すの履歴・ペン・表示)は、曲パックを開き直すまで譜面ごとに持つ。別の曲パックを開くとき、
  ファイルにしていない編集があれば確かめる(開けたときに捨てる。開けなかったときは残す)
- テストプレイ(T)は本物の演奏画面で、再生位置の 1 小節前から。やめる(← / Esc / ✎ / 終了)と編集画面の
  止めた位置へ戻る。譜面を読み終える前にやめたら位置とループは変えない

## 2. 座標

- **u**: 4/4 の小節を 1 とする拍に比例した縦の座標。`U[m] = Σ L[k] (k < m)`(L は小節長)。小節 000 の頭が u = 0、
  リードインの小節は u ∈ [-1, 0)。`u(m, tick) = U[m] + L[m] × tick / 384`。BPM を変えてもチップは動かない(時間だけ変わる)
- **tick**: 小節を 384 等分(パーサと同じ。`pos = (m + 1) × 384 + tick`)
- **画面**: 未来が上。再生位置の線は画面の高さの 75 %(既定。変えられる。§9.4)。`y = headY − (u − uHead) × 400 × zoom`(論理 px)。
  拡大率は 0.25〜5.6 の 10 段。横は演奏画面と同じ 1920 幅の論理座標で、列の絵も演奏画面と同じ
- **配置**: キャンバスが 720 CSS px 以上なら広い配置(BPM レーン・小節番号の欄・レーン)、狭ければ小節番号の欄とレーン
  (BPM は小節番号の欄に ♩ で出す)。拡大率は配置ごとに覚える。タッチの初めは 1/16 のセルが約 24 CSS px になる拡大率。
  狭い配置のタッチでは −/＋ を出さない(2 本指で拡大する。ツールバーにペン / 選択の切り替えを残すため)

### 2.1 ガイドと吸着

- ガイド間隔は 1/4・1/8・1/12・1/16・1/24・1/32・1/48・1/64・フリー。線 k は小節の頭から k/d(4/4 の小節を 1 とする)の位置で、
  tick は `floor(384 k / (d L))`。小節長が 1 でないときも音楽の拍に合う(3/4 の 1/16 は 32 tick 刻み)
- 吸着はいちばん近い線(同点は後ろ)。小節の終わりの短いセルは次の小節の頭に寄る。フリーは tick の四捨五入。
  (変更) DTXC は下へ切り捨てる(チップの中心が押した位置に来ないため)
- 1 ガイド進める・戻す(↑↓・塗り)は、線の tick が割り切れない小節でも必ず次の線へ進む

## 3. 列とチップの種類

| 列 | LC | HH | LP | SD | HT | BD | LT | FT | CY |
|---|---|---|---|---|---|---|---|---|---|
| チャンネル | 1A | 11 / 18 | 1B / 1C | 12 | 14 | 13 | 15 | 17 | 16 / 19 |

- 2 種類ある列(HH 閉 / 開、LP / LBD、CY / RD)は「今の種類」を持つ。初めはその列でいちばん多いチャンネル。
  列名の帯を押す・タッチのツールバーで切り替える。Alt を押しながらの操作はもう一方の種類
- ぶつかり: 同じセル(小節・tick)の同じチャンネル、または HHC と HHO。LP と LBD・CY と RD はぶつからず、同じセルに並べて
  描く(左右に半分ずつ)
- ペン(新しく置くチップの値 = #WAV の番号)はチャンネルごと。初めは(1)そのチャンネルでいちばん多い値 →(2)`#WAV` の
  ラベルかファイル名がチャンネルの言葉(`hhc|hh|hat|close` など)に合うもの →(3)同じ列のもう一方の種類のいちばん多い値 →
  (4)使っていない番号(音は合成音)。列名の帯の右クリック / 長押しで選ぶ。選択のモードでチップを 1 つだけ選ぶと、その列の
  ペンがそのチップの値になる(スポイト)
- 列を移したチップは、移った列の今の種類とそのペンの値になる(Alt で落とすと値はそのまま)。種類の切り替え(R)もペンの値に
  する(Shift+R・Alt+クリックの Shift で値はそのまま)。(変更) DTXC は番号を残すので、SD のチップを HT へ移すとスネアの音のまま
- ギター / ベース・BGM・SE などのチャンネルは編集しない(そのまま残る)。`#IF` の中の行は書き換えない(§8)

## 4. ペンのモード(既定)

押したところで何が起きるかは、置く前に影(枠)で見せる。

```
1. 列 col で、押した位置から遊び(チップの半分 + マウス 5 / タッチ 14 CSS px)以内の編集できるチップ → そのチップ(消す・動かす)
2. 吸着したセルが 999 小節より後ろ → 置けない
3. セルに、表示している分岐のチップでぶつかるものがある → 置けない
4. セルに同じチャンネルのチップ → そのチップ
5. セルにぶつかる別の種類(HHC↔HHO)→ 置き換える
6. それ以外 → 置く(LP/LBD・CY/RD の相方がいれば並べる)
```

| 操作 | マウス / ペン | タッチ |
|---|---|---|
| 置く | 空いたところを押す(押したときに音)。押したままドラッグすると同じ列に 1 ガイドごとに塗る(1 手)。4 px 動かすまでは塗らない。フリーでは 1 tick ごとに埋めず、指している所だけ | タップ(離したとき) |
| 消す | チップを押して離す。右クリック / 右ドラッグ(なぞった所を 1 手で) | チップをタップ(「元に戻す」付きのお知らせ) |
| 動かす | チップを押してドラッグ(Ctrl でガイドに合わせない、落とすとき Alt で値を残す) | 長押しで持ち上げてドラッグ |
| 種類 | Alt+クリック(チップなら切り替え、空きならもう一方の種類を置く) | 長押し → メニュー |
| 相方 | Shift+クリック(LP / CY の列で、もう一方の種類を横に置く) | 長押し → メニュー |
| メニュー | 小節番号の欄の右クリック | 空きの長押し・チップを長押しして離す・小節番号の欄の長押し |
| スクロール | ホイール・右のバー | 1 本指のドラッグ(慣性つき。チップの上から始めても) |
| 拡大 | Ctrl+ホイール・− ＋ | 2 本指 |

- ペンで書くと選択は外れる(書くたびに枠が付かないように)。選択のモードで選んだものはペンに戻しても残り、R・Delete が効く
- Apple Pencil(`pointerType: 'pen'`)はマウスと同じ。ペンを使っている間とその後 1 秒は、指のタップを無視する(手のひら)。
  マウス / ペンで操作している途中は、指の身振り(スクロール・長押し・取り消し)がそれを横取りしない
- メニューの外を押して閉じたときは、その押しで書かない
- 画面の上下の端 40 CSS px でドラッグすると自動でスクロールする(押しただけの手ぶれでは始めない)

## 5. 選択のモード(DTXC の選択モード)

| 操作 | マウス / ペン | タッチ |
|---|---|---|
| 選ぶ | チップ / BPM の印を押す(Shift で足す、Ctrl / ⌘ で入れ替え)。選んでいたものを押して離すとそれだけにする | タップで選ぶ / 外す |
| 範囲で選ぶ | 何もないところからドラッグ(Shift / Ctrl で今の選択に足す)。枠が掛かる列と、広い配置では BPM レーン。チップは中心が枠から半分の高さまで出ていても入る。`#IF` の中は入らない | 何もないところを長押ししてからドラッグ |
| 外す | 何もないところをクリック・Esc | 何もないところをタップ |
| 動かす | 選んだものの上からドラッグ。つかんだものをガイドに合わせ、ほかは同じだけ。BPM の印は縦だけ | 選んだチップの上からドラッグ(ほかはスクロール) |
| メニュー | 右クリック(選んでいないチップの上なら、先にそれだけを選ぶ) | 長押し(動かさずに離す) |

- 動かす・貼る・複製で行き先にあったぶつかるチップは消える(動かしたものが勝つ。消えた数をお知らせ)。動かすもの同士が
  同じセルに来たら、元の位置が行き先にいちばん近いものを残す。行き先に表示している分岐のチップがぶつかれば、移動ごとやめる。
  はみ出すときはブロックごと寄せる(リードインより前・999 小節の最後の tick より後ろ・列の外へ出さない)。(変更) DTXC は
  出られないチップだけ置いていく
- ↑↓ は選んだものを 1 ガイド(Alt で 1 tick)動かす(値はそのまま。続けて押すと 1 秒の間は 1 手)。←→ は隣の列へ
- ボーナスの印(0x4C〜0x4F、値はレーン + 1)はチップについて動き、チップと一緒に消える。ボーナスのチップを置き換えたチップは
  ボーナスを引き継がない。CY↔RD に切り替えると印の値も替える

### 5.1 クリップボード

- コピーは選んだもののいちばん前からの u の差で持つ。BPM の印は BPM の値で持つ。(変更) DTXC は `#BPMzz` の番号で貼るので、
  別の譜面では別のテンポになる
- クリップボードはページの中で 1 つ(別の譜面にも貼れる。DTXC と同じ)。切り取り = コピーして消す(1 手)
- 貼る位置(ガイドに合わせる): メニューから → メニューを開いたセル、キーから → マウスで指しているセル(レーンの上なら)、
  無ければ再生位置。(変更) DTXC はメニューの左上の位置。列とチャンネルはそのまま。貼ったものを選ぶ
- 複製(Ctrl+D。本アプリの追加): 選んだ小節の数だけ後ろの小節へ、小節の中の tick のまま写す(小節長が違っても拍の頭が揃う)

### 5.2 メニュー

```
切り取り / コピー / 貼り付け / 削除 / 後ろの小節に複製
──
すべて選択 / レーン内をすべて選択 [SD] / 小節内をすべて選択 [012]
──
種類を切り替え (R) / (LP・CY のチップを 1 つ選んでいれば){種類} も置く
──
ここに BPM… / 小節長… / 小節の挿入 / 小節の削除
──
ここから再生 / ここからテストプレイ / この小節を繰り返し再生(選んでいれば、選んだ小節)
```

切り取り・コピー・削除・複製・種類は選択が要る。貼り付けはクリップボードが要る。↑↓ で動き、Enter で決める
(Space は BD のキーなので押さない)。小節番号の欄のメニューは小節の操作と再生だけ。

## 6. BPM

- 広い配置の BPM レーンを押す: 印の上ならその BPM を変える / 消す、空きならガイドに合わせたセルに新しい BPM。
  ペンのモードで印を右クリックすると消す。狭い配置ではメニューの「ここに BPM…」(そこに印があればそれを変える)。
  選んでいる印が 1 つだけなら Enter で変える
- ダイアログ: 0.0001〜1000、小数 4 桁まで(DTXC の数値入力と同じ範囲)。初めの値はそこの今の BPM。範囲の外では閉じない
- 書き方:
  1. 小節 000 の頭で印が無ければ、「曲の BPM (#BPM) を変える」(既定で入)で `#BPM` を書き換える(#BASEBPM は引かない)
  2. それ以外は印の値 = BPM − #BASEBPM(無ければ 0)。0 以下なら断る
  3. そこにあった ch 03 の印を変えるとき、値が 1〜255 の整数なら ch 03 のまま(16 進 2 桁)。ほかは ch 08。
     (変更) DTXC は読むときに ch 03 をすべて ch 08 に替える(差分を小さくするため替えない)
  4. ch 08 の番号: 同じ値の `#BPMzz`(`#IF` の外で 1 回だけ定義されたもの。値は書いた文字列で比べる)があれば使い回す。
     無ければ 01〜ZZ の空きのいちばん小さい番号(`#IF` の中の定義も避ける)を `#BPM…` の最後の行の後ろ(最初のデータ行より前)に足す。
     空きが無ければ断る
  5. 書き出すとき、この編集で足して使われなくなった `#BPMzz` の行を消す(元の譜面にあった定義は消さない)
- BPM を変えてもチップは動かない(u が同じ。時間だけ変わる)

## 7. 小節

### 7.1 小節長

小節番号の欄・メニューの「小節長…」。拍子(4/4・3/4・2/4・5/4・6/8・7/8・12/8)か倍率(0.01〜16、小数 6 桁まで)。

- 範囲: この小節だけ(既定。DTXC の「後続」なし)/ ここから(次に小節長を書いた小節の前まで。DTX の小節長の続き方そのもの)
- チップ: 拍の位置を保つ(既定。DTXC と同じ。`tick' = round(tick × L旧 / L新)`、どのチャンネルも。384 以上になるものは消え、
  消える数を OK の前に出す)/ 小節に合わせて伸縮(tick はそのまま。本アプリの追加)
- ch 02 の行は「前の小節と同じなら書かない、違えば書く(同じ値の行が元からあれば残す)」で直す。この小節だけのときは
  次の小節に元の長さを書き戻す
- `#IF` の中の ch 02 が関わる、または拍を保つのに `#IF` の中の行を動かすことになるときは変えない
- 1 手。(変更) DTXC は小節ごとに 1 手

### 7.2 小節の挿入 / 削除

- 挿入: 押した小節の前に空の小節を挿し、押した小節から後ろが 1 つ後ろへ(`#IF` の中の行も)。新しい小節の長さは押した小節と同じ、
  押した小節の頭の BPM の印も写す。(変更) DTXC は長さ 1・テンポ無し(3/4 やテンポの変わった所に挿すと拍子とテンポが変わる)
- 削除: 小節を消して詰める。消えるものがあれば種類ごとの数(ドラム・BGM・BPM の変化・そのほか・分岐の中の行)を見せて確かめる。
  BGM の開始チップがあればそう書く。小節の中の最後の BPM の変化は、次の小節の頭に印が無ければそこへ移す。後ろの小節の長さも
  保つ。(変更) DTXC は消した小節のテンポと長さの影響が後ろに出て、元に戻すと長さが戻らない
- 999 小節を超えるとき、`#IF` の中に小節長の行があるとき(表示している分岐の長さを `#IF` の外に書いてしまうため)は断る。
  演奏画面から持ってきたループの位置もずらす(元に戻すと戻る)

## 8. `#RANDOM` / `#IF`

- `#IF` の中の行は読むだけ(書き換えない・動かさない。新しい行は `#IF` の中に入れない)。表示する分岐は、演奏から来たときは
  その演奏の乱数、無ければ下書きのとき、無ければ分岐 1。表示している分岐のチップは斜線で描き、その位置には置けない
- 小節の挿入 / 削除だけは `#IF` の中の行の小節番号も動かす

## 9. 再生とテストプレイ

- ▶ / P: 再生位置から全部 AUTO で鳴らし、再生位置を追う(スクロールすると追うのをやめる。⇩ で戻る)。止めると止めた位置に
  とどまる。(変更) 演奏画面の停止は開始位置へ戻る。Shift+P は先頭(リードイン)から
- メトロノーム(M)・ドラムの音・再生速度 x0.5〜x1.5 は ⋯ から。トレーニングの設定には触れない(`EditorPlayer` は自分の設定を持つ)
- 「この小節を繰り返し再生」: その小節(選んでいれば選んだ小節の範囲)を繰り返す。折り返すと演奏画面のループと同じく 1 小節前から
- 再生中に書き換えると、次の再生から反映(お知らせ)。新しい番号の音はあとから読む
- 置いたときに音を鳴らす(⋯ の「置いたチップの音を鳴らす」。DTXC と同じく既定で入)。音が無ければ列の合成音。電子ドラム
  (Web MIDI)で叩くと、その列のペンの音を鳴らし列を光らせる(「叩いて入力」でなければ書きはしない)

### 9.1 叩いて入力(本アプリの追加。DTXC に無い)

ツールバーの「叩いて入力」で入る / 切る。叩いた列(電子ドラム・キーボード)のチャンネルは、HH・LP・CY の列の今の種類
(電子ドラムの RD は RD)。音はその列のペン。

- 止まっているとき: 再生位置のセル(ガイドに合わせる)に置く。60 ms の間に叩いたものは同じセルに置いて 1 手(和音)。置いたら
  1 ガイド進む(⋯ の「叩いたら進む」。既定で入。フリーのときは 1/16)。同じチャンネルのチップがもうあれば鳴らすだけ
- 再生中(ボタンが「● 録音」になる): 叩いた譜面時刻(演奏の判定と同じ式。判定タイミング調整を含む)のセル(ガイドに合わせる)に
  録音する。録音しかけのチップは赤い枠で描き、止めたとき(最後まで行ったとき・閉じたときも)に 1 手(「n 個を録音しました」)。
  同じセルの同じチャンネルは 1 つ。リードインで叩いたものは置かない。判定タイミング調整はトレーニングの設定の値(書きはしない)
- キーボード: 入っている間は、設定のキー割り当て(演奏と同じ)のキーがレーンになる(Space の BD も)。割り当てていないキーは
  いつもどおり(P で再生 / 停止して録音できる)。Ctrl / ⌘ の組み合わせと Alt を押したキーはショートカットのまま。押しっぱなしの
  繰り返しは使わない

### 9.2 演奏画面のプレビュー(本アプリの追加。DTXC は外部のビューアで見る)

ツールバーの「プレビュー」/ V で、右のバーのさらに右に演奏画面と同じレーン(チップ・小節線・小節番号・判定ライン・パッド)を
並べる(出すかは覚える)。演奏画面の描画(`Renderer`)を継承して使い(`js/edit/preview.js`)、演奏画面の縦画面と同じ範囲を
切り出す。成績・ゲージ・コンボ・曲のパネルと状態の文字は描かない。チップの絵の作り置きは編集画面と別に持つ(スキンはレーンごとに
1 つしか持たないので、同じフレームで別の大きさを頼み合うと毎フレーム作り直す)。

- 止まっているとき: 編集画面の再生位置を判定ラインに合わせる(過ぎたチップは消えている)。書き換えはすぐ映る(譜面を差し替える)
- 再生中: 編集画面の再生(`EditorPlayer`)をそのまま流す(再生中の書き換えは、編集画面の再生と同じく次の再生から)。
  判定の文字は AUTO で叩いたものだけ(「ドラムの音」を切って鳴らすとチップは MISS になるので出さない)
- ハイスピードはトレーニングの設定の値(読むだけ。止まっていても変えた速さですぐ描く)。編集画面だけの値にもできる(§9.4)
- 縦の位置(判定ラインの位置を決めていないとき。決めたときは必ずそろえる。§9.4): 縦長の場所(iPad の縦・寄せたパネルで細いときなど)では、判定ラインを編集画面の再生位置の線にそろえる。横長の窓
  ではプレビューが高さいっぱいになって動かす余地が無いので、演奏画面と同じく上に寄る(判定ラインは再生位置の線より下)。
  ハイウェイの上を切ってまではそろえない(演奏画面に見える範囲をそのまま見せる)。(変更) 演奏画面の縦画面は上に寄せる
  (下をメニューに使う)
- 幅: 編集の場所(右のバーを除く)の 4 割まで(と下の決まり)で、場所の高さに合わせて詰める。その上限が 160 CSS px に届かない
  なら出さない(お知らせ。出すことは覚えておき、広げると出る)。高さは出すかどうかには使わない(低い窓でも 160 CSS px は取り、
  描くほうが高さに合わせて縮める。高さで決めると、広げたら消えるといった食い違いが出る)
- 編集画面の配置(広い / 狭い)は場所の幅と横のパネルだけで決め、高さやプレビューの幅にはよらせない(よらせると、狭い配置の
  ツールバーの段と横のパネルの寄せ方で場所の大きさが変わり、配置が毎フレーム入れ替わる)。場所の幅は、これから決める
  パネルの寄せ方でのもの(今の寄せ方のまま測ると、寄せたパネルを閉じた直後に一度だけ狭い配置を挟み、拡大率が入れ替わる)。
  広い配置なら、残りが狭い配置になる幅(`COMPACT_BELOW` = 720 CSS px)を割るほどは取らない。ただし横のパネルを寄せない窓で、
  場所が 720〜880 CSS px(広い配置のままでは並べられない幅)なら、狭い配置にして並べる(それより狭い窓では出るのに、広げると
  消えないように。iPad の縦など)
- 広い配置で横のパネルを右から重ねている(寄せない幅の窓)ときは、プレビューがその下に隠れるので出さない。出せないとき、パネルが
  隠しているか、パネルを閉じれば出せる幅なら「横のパネルを閉じると、プレビューを出します」、ほかは「画面が狭いので…」と知らせる
- プレビューの上のホイールは譜面を送る。押しても何もしない

### 9.3 プレー動画を並べる(本アプリの追加。DTXC・V2D に無い)

ツールバーの「動画」/ B で、右のバー(プレビューを出していればその右)に DTXMania などのプレー動画を並べ、止まっていれば
再生位置、再生中は鳴っている所に合わせて流す(出すかは譜面ごとに覚える)。目的は、編集中の譜面(とプレビュー)と元のプレー動画を
見比べて直すこと。SoundVoltexAnalyze の譜面の編集の「動画」(`tool/sim/js/voxeditvideo.js`。同 `docs/譜面シミュレータ.md`
§17.7.2)を移した(`js/edit/video.js`・`videosync.js`・`videoalign.js`)。動画は鳴らさない(muted。鳴るのは編集画面の曲だけ)。
上でのホイールは譜面を送る。判定・叩いて入力には何も流さない。

- **写し方**: 動画の秒 = (譜面の時刻 + ずれ) / 1000(譜面の時刻はリードインの小節を含む)。ずれは BGM の頭(最初の BGM チップ)の
  動画の時刻として、動画ごと(名前と大きさ)に覚える(localStorage の `dojo.editVideo`。`charts[譜面].files[名前|大きさ].syncMs`)。
  BGM を動かす(「BGM をずらす」)・頭に小節を足す・頭の BPM を変えても、動画は BGM の音と一緒に動く(プレー動画の音は BGM
  そのもの)。BGM が無い譜面は譜面の時刻 0 が基準。基準は「今の譜面の一番早い BGM チップ」なので、そのチップを消す(小節ごと消すなど)と
  次の BGM チップが基準になり、その差だけ動画がずれる。`#IF` の中の BGM チップは「BGM をずらす」で動かないので、それが一番早いと
  動画も付いてこない。(変更) SoundVoltexAnalyze の手元のファイルは譜面の時刻 0 が基準で、小節を足し引きすると知らせていた
- **動画の元**: 手元のファイル(見出しの元のボタンのメニュー・空の枠の「動画のファイルを選ぶ…」・編集画面へのドロップ)。ファイルは
  そのページに残す(閉じて開き直す・テストプレイから戻るときは選び直さない)。Chromium で選んだ(`showOpenFilePicker`)・ドロップ
  したファイルはハンドルを IndexedDB(`videoHandle:<譜面>`)に残し、ページを読み直したら読む許可があればそのまま、無ければ
  枠の「前の動画を開く」で開く(許可は押したときだけ聞ける)。同じページで開き直すときもハンドルがあれば読み直す(テストプレイの
  間にファイルを書き替えても読める)。好みから消した古い譜面のハンドルは消す。「動画を外す」でこの譜面では使わず枠もしまう(ずれ・
  切り出しは動画ごとに残す)。読めない形式は枠に「動画を読めません(…)」。(変更) SoundVoltexAnalyze の、動画から起こした譜面の記録で自動で
  合わせる動画とサーバに登録するパスは無い(サーバが無い。代わりに下の「音で合わせる」)
- **音で合わせる**(♪・メニュー。初めて使う動画(ずれを覚えていない)は読み込んだらひとりでに。ひとりでに試すのはページで 1 回で、
  合わせ終わる前に閉じたら開き直したときに。400 MB まで、手で押せば 1.5 GB まで): 動画の音
  (ファイルを丸ごと読んで `decodeAudioData`、8 kHz・1 本)と、読んである譜面の音(BGM・BGM と SE・それにギター / ベースのチップ・
  ドラムのチップまで、の 4 通りを `OfflineAudioContext` で譜面の時刻に置く。音量は `#VOLUME`。空ピックの音の切り替え・隠れたチップは
  それだけでは鳴らないので置かない)の音の立ち上がりの強さ(10 ms の窓の
  RMS の対数の正の差を 5 ms ごと)を
  FFT で相互相関し、全部のずらしから一番重なる所を探す(動画の頭の曲選び・読み込みの画面の長さは分からないので)。峰の高さ ÷ 峰の
  ±60 ms の外の 2 番目の高さ(どちらも平均から)が 1.4 以上の候補のうち一番はっきりした物で決め、1 ms の刻みで峰の前後を見て放物線で
  補う。届かなければ合わせずに知らせる。合わせたら、前のずれへ(初めてならずれを覚えていない形へ)戻すボタン付きで知らせる。
  覚えるのは測った譜面の BGM の頭の動画の時刻(合わせている間に譜面を変えてもずれない)。合わせている間に動画を替えたら、その結果は
  捨て、替えた動画は別に合わせる。
  確かめ(2026-10-23。APPROVED DTX 1278「絵空事」の mstr.dtx と、その曲の DTXMania のプレー動画 1280x720 60 fps): 峰の比は BGM
  2.88・BGM と SE(ドラムの分割の音)1.91・全部 1.65 で、ずれ +1563.0 ms(Python の波形の相関で +1563.4 ms)。ほかの曲の BGM を
  相手にすると比 1.03〜1.21(峰の高さの z はほかの曲でも 20 を越え、見分けに使えなかった)。この録画の音は絵より約 14 ms 遅れる
  (vid2dtx がチップの判定ラインの通過から求めた絵のずれは +1549.5 ms)ので、合わせた後に ◀ を 1 回(−1 コマ)押すと絵がそろう
- **ずれ**: 見出しの ◀ ▶ で 1 コマ(Shift で 10 コマ、Alt で 1 ms)、値を押すと数で入れる。1 コマの長さは流したときに見えたコマの間で
  測ったコマの速さ(分かるまでは 60 fps。動画ごとに覚える)。(追加) SoundVoltexAnalyze は手元のファイルを 60 fps とみる。30 fps の
  録画では 1 コマ・半コマがずれるので測る。画面の Hz より速く流すとブラウザはコマを飛ばして見せ、間が 1 コマの倍数に延びるので、短い方
  の 1 割の所から 1.5 倍までの間だけを平均し、よくある速さ(15〜144)の 1.5 % の内に寄るときだけ使う。前のコマから画面の 1.5 フレーム
  以上たって出たコマの間だけを集める(画面の Hz がコマより遅い(省電力の 30 Hz など)と、どのコマも飛ばして半分の速さに見えるので。
  60 Hz の画面の 60 fps の動画は測らず 60 のまま)
- **止まっているとき**: 的(再生位置の動画の秒)に一番近いコマを出す。Chrome は止まっている動画を seek するとその時刻を含むコマを
  出すので、的 + 半コマへ seek する。最後の seek の後に見えたコマ(`requestVideoFrameCallback` の `mediaTime`)が的から半コマの内なら
  seek しない。seek は重ねず、着いたら最後の的だけを追う。動画の頭より前・終わりより後は端のコマで止めて暗くし、「動画の外」
- **再生中**(SoundVoltexAnalyze の合わせ方。数値の根拠はあちら): 動画の速さ = 編集の速さ。再生の頭は、音が聞こえ始めるまで
  (出力の遅れの間)編集の時計を開始位置で止めたものを的にし(`EditorPlayer.videoClock`)、その残りが動画の動き出しの遅れになったら
  流す。動き出しの遅れは見えたコマで測り(play の直後の `currentTime` は 1 コマ進んでから止まるので測れない)、ページで覚える。
  ずれは見えるコマで見る(見えるコマ − `currentTime` の平均を速さごとに測って足す)。ずれが 6〜12 ms を越えたら ±2 %、30 ms を
  越えたらずれに比例して(0.4 秒で寄せ切る速さ、15 % まで)寄せ、60〜300 ms 遅れれば 15 % 速めて追い付き、0.5 秒まで先なら止めて待ち、
  それより離れれば止めて先へ seek して待つ(区間の折り返しなど)。`preservesPitch` を切る(muted。真のままだと速さを替えるたびに
  23〜28 ms 止まる)。終わった動画には play を呼ばない(頭へ戻る)。本アプリの追加が 3 つ:
  (1) 30 ms を越えたら比例して寄せる。ページで初めての「seek して止めて待ってから流す」は動き出しの遅れの見込み(100 ms)が実際
  (34 ms)より長く、止めて待っても流し直した直後に 1 コマ進むので +55 ms のまま、±2 % では 2.5 秒残った。seek の後の遅れを測る前は、
  止まっていた所から流すときの遅れを見込みに使う。(2) 動画の頭より前から流すとき(ずれが負)は、的が頭に着くまでの残りを始めの待ちとみて
  着く前に流し始める(着いてから流すと動き出しの遅れの分だけ遅れ、その後の待ちの間は寄せない)。(3) 止めて待っている間・play の後の
  待ちの間に的が大きく飛んだら(頭から鳴らし直した・別の区間を繰り返した。待ち始めた所から時計どおりに進んだ所と 0.5 秒より離れた)、
  待ち切らずに seek し直す / 待つのをやめる(1.5 秒の待ちの後に流してから seek していた)。seek が遅くて遅れて着いただけ(的は時計
  どおり)なら、待ち切って流し、追い付いて直す
- **(変更) 編集画面の再生の速さ**は、鳴らし始める前に反映する(それまでは鳴らし始めた最初のフレームで反映し、今の実時間で時計を
  つなぎ直すので、再生の頭の出力の遅れの間の待ちが消えて時計が数十 ms 戻っていた。動画はその待ちで流し始めを決める)
- **確かめ**(2026-10-23。ヘッドレス Chrome 155・GPU、1920x1080。上の曲と動画。ずれは編集画面の毎フレームの的と比べ、編集の時計が
  動き出してから 1 秒より後): 止まっているときの見えるコマは、5〜60 小節の頭で的の −0.18 コマ、再生を止めた後は ±0.5 コマの内。
  10〜50 小節から 6 秒の再生(×1.0 を 5 回・×0.5・×1.5。3 回の通し)で `currentTime` − 的の最大 3.3〜14.0 ms、見えるコマ − 的の平均
  −5.5〜+6.8 ms(1 つ 1 つのコマは的から 1〜2 コマ離れることがある)、seek・止めて待つは 0 回。小節 20〜21 の繰り返し(1 小節前から
  流して折り返す)は、折り返しのたびに seek 1 回、0.3 秒で 10 ms の内、1 秒より後の最大 3.5〜14.6 ms。窓の大きさ 7 通り(1920x1080〜600x800、パネルの開け閉め)で配置は毎回同じ、選曲へ戻って
  開き直すのを 5 回くり返しても object URL は毎回捨てる
- **置き方**: 右のバー・プレビュー・動画の順。枠の幅は、見える縦横比(切り出していればその範囲)× 場所の高さ(見出し 34 px を
  除く)を、場所の幅の 45 % まで、240 CSS px 以上。出すかどうかと配置(広い / 狭い)は幅だけで決める(§9.2 と同じわけ)。広い配置
  なら編集画面に 720 CSS px を残し、プレビューと両方は入らなければ広い方から同じだけ縮め(プレビュー 160・動画 240 まで)、それでも
  入らなければ動画を出さない(プレビューが先)。横のパネルを寄せない窓で広い配置のままでは並べられない幅(720 + 並べる物の最小の
  幅の和 未満)なら狭い配置にして並べ、そのときと元から狭い配置のときは編集画面に 400 CSS px を残す。重ねた横のパネルの下には
  出さない。出せないときは、パネルのせいなら「横のパネルを閉じると、動画を出します」、プレビューをしまえば入るなら「…プレビュー(V)を
  しまうと動画を出します」、ほかは「画面が狭いので…」と知らせる
- **切り出し**(✂・メニュー): 横長の動画(画面の録画)はレーンの外が多く小さく見えるので、ドラッグで残す範囲を囲む(Enter で決める・
  Esc でやめる・「全体」で外す。押しただけなら前の囲みのまま)。切り出しの間は動画を止め、枠は動画の全体の縦横比の幅を取る(囲み
  やすいように)。枠が隠れたら(パネル・狭い窓)切り出しをやめる。動画ごとに覚え、切り出した範囲を枠いっぱいに出す(枠の幅もその
  縦横比)。横長の動画を読んで 8 秒は、見出しの下に「✂ でレーンだけを切り出すと大きく見えます」。狭い配置で横のパネルを下から
  出しているときは、パネルに隠れないよう選ぶボタン・切り出しのボタンを上に寄せる
- **限り**: 形式はブラウザが鳴らせる物だけ(Chrome は H.264 / VP9 / AV1 の mp4・webm・mov)。音で合わせるのはファイルを丸ごと
  メモリに読むので大きい動画は重く、音の通り道の無い動画・ブラウザが読めない音は合わせられない(◀ ▶ か数で合わせる)。音で合わせた
  ずれは録画の音と絵のずれ(上の例で約 1 コマ)を含む。`decodeAudioData` は入れ物の中の音の始まりの時刻(mp4 の edit list の遅れ・
  webm の最初の音の塊の時刻)を見ないので、音が絵より後から始まるファイルではその分だけずれる(レビューの確かめで、音の頭を 34 ms
  遅らせた webm で 34 ms、40 ms 遅らせた mp4 で 18 ms)。見えるコマのずれ・動き出しの遅れはページで覚え、動画で分けない(コマの長さの
  違う動画に替えると数回の再生で測り直す)。1 つ 1 つのコマはブラウザがコマを落とすので的から 1〜2 コマ離れることがある

### 9.4 判定ラインの位置とプレビューのハイスピード(本アプリの追加)

プレー動画(§9.3)と見比べるため、判定ラインの高さとプレビューのチップの速さを細かく合わせる(`js/edit/previewbar.js`)。
演奏画面のプレビューの上端に細い帯を重ねる(「判定 ▲ 75.0 % ▼」「HS − 1.00 ＋」「⋯」。プレビューを出しているときだけ。
入りきらないプレビューでは字を詰め、それでも入らなければ ▲ ▼ − ＋ をしまう(値を押して数で入れる・⋯ は残す))。編集画面の「その他」の
メニューにも「判定ラインの位置…」「プレビューのハイスピード…」とそれぞれの戻す項目。

- **判定ラインの位置**: 編集画面の再生位置の線とプレビューの判定ラインを一緒に動かす(場所の高さに対する上からの割合、5〜98 %。
  既定は前からの 75 %。上の列名の帯の下まで)。▲ ▼ で 2 px(Shift で 20 px、Alt で 0.5 px。線は画面の画素に合わせて丸める)、値を
  押すと % で入れる。編集画面全体の設定(`editJudgeY`)。
  既定のときのプレビューは前のとおり(ハイウェイが収まる範囲でそろえる。§9.2)、位置を決めたときは必ずそろえる(ハイウェイの上や
  パッドが切れてもよい)。⋯ の「判定ラインを標準(75 %)に戻す」で既定へ(動画の印も外す)
- **動画に合わせる**: 動画の見出しのメニュー・帯の ⋯ の「判定ラインを動画に合わせる…」で、動画の判定ラインを押す(Esc でやめる)。
  押した高さを動画の高さに対する割合として動画ごとに覚え(`files[…].judgeV`)、動画に点線の印を出す(押せるのは動画の大きさが
  分かってから。切り出しを始めると押すのはやめる)。印があって動画を出している間は、
  判定ラインがその高さに付いていく(窓の大きさ・切り出しを変えても)。▲ ▼ と値はその印を直す。「判定ラインを動画に合わせない」で
  印を外す(設定の位置に戻る)。確かめ(絵空事のプレー動画を切り出して 1920x1080): 動画の判定ラインを押すと、再生位置の線と
  プレビューの判定ラインが押した高さ(779 px。画素に丸める)に来て、▲ 3 回でちょうど 6 px 上へ、1366x768 にしても動画の印(521 px)に付いていく
- **プレビューのハイスピード**: 編集画面だけの値(`editHiSpeed`。0.1〜200)。− ＋ で 0.05(Shift で 0.5、Alt で 0.01)、値を押すと数で
  入れる。決めていなければトレーニングの設定の値(前のとおり。0.1 刻み)で、編集画面からトレーニングの設定は変えない
  (`EditorPlayer.hiSpeedOverride`)。⋯ の「ハイスピードをトレーニングの設定に戻す」で戻す。チップの間隔は画面の大きさで変わるので、
  動画とそろう値は窓の大きさによる

## 10. 保存

### 10.1 書き方(`DtxDoc`)

- 変えた(小節, チャンネル)の組の行だけを書き直す。触っていない行は元のバイト列のまま。書き直した組は元の最初の行の場所に、
  新しい組はチャンネルの並びの近くに入れる(`#IF` の中には入れない)
- チップの行は `#MMMCC: data`(小節 3 桁、チャンネルは大文字 16 進、data は空白なし)。分割数は全部のチップが割り切れる最小の数。
  同じ tick に同じチャンネルのチップが 2 つあれば行を分ける。小節長は小数 6 桁まで、BPM は 4 桁まで(`.`、指数なし)
- 文字コードと改行は元のまま。書き直した行が Shift-JIS で書けなければ全体を UTF-8(BOM 付き)にする(NX は BOM で見分ける。
  vid2dtx は読めないのでお知らせ)。書き直した文書は改行で終える(DTXC は改行の無い最終行を読み落とす)
- ⋯ の「文字コード」で、元のまま / Shift-JIS / UTF-8(BOM 付き)を選べる。Shift-JIS で書けない文字があれば変えない
- 編集の印になるものは足さない。(変更) DTXC は `#DTXC_CHIPPALETTE` などを書く

### 10.2 渡し方

- 保存(Ctrl+S): .dtx をダウンロード。「名前を付けて保存…」(Ctrl+Shift+S。Chromium だけ)で選んだファイルがあれば、
  以後の保存はそこへ上書き(上書きできなければダウンロードにして、そう知らせる)
- 共有…(iPad / スマホ): AirDrop・ファイル App など
- 曲フォルダを ZIP で保存 / 曲パックを ZIP で保存: 元の ZIP の中身は圧縮したまま写し、編集した譜面だけを入れ替える
  (名前は `<元の名前>_edited.zip`)。曲パック全体のときは「前回の ZIP」にも残す。フォルダから読んだ曲パックは全部の
  ファイルを読み直す(お知らせ)
- 下書き: 編集は書き換えて 1.5 秒後・閉じたとき・タブを隠したときに IndexedDB に書く(新しいものから 30 件まで)。次に同じ譜面を開くと
  続きを開くか聞き、曲パックを開いたときにも戻すか聞く

### 10.3 フォルダへの上書き保存(Chromium だけ。本アプリの追加)

ホームの「フォルダを開く(上書き保存できる)」(File System Access の `showDirectoryPicker`。書き込みの許可を聞く)で開いた
曲パックでは、保存(Ctrl+S)がそのフォルダの譜面のファイルへの上書きになる(⋯ には「上書き保存」と、ダウンロードの
「譜面を保存 (.dtx)」の両方)。

- この画面で初めて上書きする前に、元のファイルを `<名前>.bak` に写す。`.bak` が既にあれば触らない(vid2dtx と同じ)
- 上書きしたあとは、そのファイルを「元」にして下書きを比べる(同じなら下書きを消す)。続けて保存しても 1 つずつ書く。
  下書きのキーは、このフォルダでは名前だけ(保存で `.bak` などが増えてもキーが変わらないように)
- 足した音源(§14)・新しい難易度の譜面も、そのフォルダに書く
- 書けなければ(許可を取り消した・ファイルを動かした)ダウンロードにして、そう知らせる
- ふつうの「フォルダを選ぶ」・ZIP では上書きできない(ブラウザはファイルを直接書けない)

## 11. vid2dtx の確信度

`<譜面>.dtx.conf.json`(vid2dtx が書く `{chips: [{m, tick, ch, conf, why?}]}`)があれば、確信度 0.7 未満のチップに枠を付ける
(0.4 未満は赤、ほかは橙)。「次の要確認」(ツールバー)/ N で確信度の低い順(同じなら前から)に回り、最後まで行ったら最初へ。
回ったチップを再生位置に置き、選ぶ(R・Delete ですぐ直せる)。理由(`why`)をお知らせに出す。動かしたチップは枠が外れる
(vid2dtx と同じく (小節, tick, チャンネル) で引くため)。ファイルは書き換えない(ZIP にはそのまま入る)。⋯ の「確信度を表示」で隠せる。

## 12. 横のパネル(本アプリの追加)

ツールバーの ☰ で開く / 閉じる(開いているかは覚える)。窓が 1100 CSS px 以上の広い配置では譜面の右に寄せ、それより狭い広い配置では
右から重ね、狭い配置では下から出す(画面の 55 %)。

- **チップ**: 選んだものの数・種類・音(番号を選ぶと選んだチップの音を全部その番号に)・位置、種類の切り替え・同じ音のチップを選択・
  コピー / 切り取り / 複製 / 削除。BPM の印を 1 つ選んでいれば BPM。下に列ごとのペン(新しく置くチップの音。DTXC のレーンに割り当てた
  チップ)
- **小節**: 再生位置の小節の番号(◀ ▶ で前後)・長さ・頭の BPM・時刻・チップの数、小節長・ここに BPM・小節内をすべて選択・
  繰り返し再生・挿入・削除
- **譜面情報**: `#TITLE` `#ARTIST` `#COMMENT` `#GENRE` `#BPM` `#DLEVEL` `#PREVIEW` `#PREIMAGE` `#STAGEFILE` `#BACKGROUND`。
  書き終えたとき(Enter・欄の外へ。Esc で戻す)に 1 手。空にすると行を消す((変更) DTXC は空の題名を「(no title)」と書く)。
  `#IF` の外の同じヘッダの行をすべて書き直す(パーサは最後の行、曲の一覧は最初の行を読むので揃える)。`#BPM` は 0.0001〜1000
  (消せない)、`#DLEVEL` は 0〜999 の整数(一覧の表示も出す)。`;` はコメントになるので空白にする。今の文字コードと、編集しない
  チップ(SE・ギター / ベースなど)の数も出す
- **音源**: 定義した番号とチップが使っている番号の一覧(番号・ファイル・ラベル・音量・位置・使用数。BGM は ♪)。番号を選ぶと試聴
  (もう一度で止める。読んでいない音はそこで読む)・ペンにする(列を選ぶ)・サウンドプロパティ・同じ音のチップを選択。
  「音源を追加…」「BGM をずらす…」(§14)

## 13. キー

演奏中の `RESERVED_CODES` とは別。Space は BD の既定のキーなので何もしない(スクロールもボタンの決定もしない)。F1 も何もしない。
文字は `e.code`(配列・IME に左右されない)、記号は `e.key`(JIS 配列の [ ] も印字どおり。IME が入力中の 'Process' だけ e.code)。
入力欄・ダイアログ・メニューが開いている間は、それぞれのキー(Enter = 決定、Esc = 取り消し)だけ。

| キー | 動作 | 手本 |
|---|---|---|
| Ctrl/⌘+Z、Ctrl/⌘+Shift+Z・Ctrl+Y | 元に戻す / やり直す | DTXC・V2D |
| Ctrl/⌘+S、Ctrl/⌘+Shift+S | 保存 / 名前を付けて保存 | DTXC・V2D / 追加 |
| Ctrl/⌘+X / C / V / D / A | 切り取り / コピー / 貼り付け / 複製 / すべて選択 | DTXC(D は追加) |
| E / S | ペン / 選択 | (変更) DTXC の Ctrl+Space は IME の切り替え |
| P / Shift+P | 再生・停止 / 先頭から | (変更) DTXC の F6 / F5 はブラウザのキー |
| T | テストプレイ | 追加 |
| M | メトロノーム | 追加 |
| V | 演奏画面のプレビュー(§9.2) | 追加 |
| B | プレー動画(§9.3)。切り出しの間は Enter で決める・Esc でやめる。判定ラインを押す間は Esc でやめる | 追加 |
| R / Shift+R | 種類の切り替え(選んだもの、無ければ指しているチップ)/ 値を残す | DTXC の表裏反転 |

## 14. 音源・BGM・新しい難易度(本アプリの追加を含む)

- **サウンドプロパティ**(DTXC と同じ項目): ラベル・ファイル・音量 0〜100・位置 -100〜100・「このサウンドをBGMとして使用する」。
  書き方は DTXC と同じ `#WAVzz: ファイル\t;ラベル`、音量は 100 以外なら `#VOLUMEzz`、位置は 0 以外なら `#PANzz`(ファイルが
  `#WAVVOL` / `#WAVPAN` だけを使っていればそれ)、BGM なら `#BGMWAV: zz`(DTXC の印。NX と本アプリは読まない)。その番号の行だけを
  書き直し、新しい行はその番号の定義の後ろ(無ければ音源の定義の最後、最初のデータ行より前)。ファイルを空にすると定義ごと消す。
  `#WAV` / `#VOLUME` / `#PAN` を 2 回以上定義した番号・`#IF` の中でも定義した番号は変えない(どれが効くかが分岐と行の順で決まるため)。
  `#PANEL` は値が整数のときだけ `EL` の位置(NX・DTXC と同じ)。#WAV のファイルを変えたら、その音を読み直す
- **音源を追加…**: 選んだファイルを曲のフォルダに入れ(曲パックに重ねる。同じ名前で中身の違うファイルがあれば `名前 (2).wav`、
  同じ中身ならそのまま使う)、空いている番号(定義・チップ・ペンのどれにも無いもの)に `#WAV` を書く。ファイルは ZIP の書き出しと
  フォルダへの上書き保存で書く。下書きには入らない(ページを開き直すと音が無くなるので、ファイルにしておく)
- **BGM をずらす…**: BGM(ch 01)のチップを ms でずらす(+ で遅く)。時間で動かしてから tick に丸める(120 BPM で 1 tick ≒ 5 ms)。
  小節 000 より前に出るならずらさない。`#IF` の中は動かさない
- **＋ 新しい難易度**(曲の一覧の「✎ 譜面を編集」で、曲ごと): 曲の最初の譜面から、`#IF` の外のヘッダ・コメントと BGM・小節長・BPM の
  行(ch 01 / 02 / 03 / 08)を写した `<名前>_edit.dtx`(あれば `_edit2` …)を同じフォルダに作って開く。レベル(`#DLEVEL` / `#GLEVEL` /
  `#BLEVEL` と小数の行)は消す(ギター / ベースのチップは写さないので)。写すのは曲のドラムの譜面。先頭に
  `; Created by DTXMania Web`。Shift-JIS・CRLF(書けなければ UTF-8 BOM)。set.def は書き換えないので、曲の一覧には別の曲として
  出る。フォルダへ書くまでは下書きに残し、曲パックを開き直したときも下書きから戻せる
- **同じ音のチップを選択**(メニュー・パネル): その番号のチップ(編集できるもの)をすべて選ぶ。(変更) DTXC の検索 / 置換の代わり
- **ほかの分岐も表示**(⋯。`#IF` があるとき): 表示していない分岐のチップも点線の枠で薄く描く
- 右のバーにチップの密度を描く(どこに譜面があるか)

## 16. まだ無いもの

- ギター / ベースのチップの編集、検索 / 置換(DTXC の Ctrl+F / Ctrl+H。「同じ音のチップを選択」だけ)
- BGM のレーンでの BGM のチップの編集(「BGM をずらす」だけ)、画像の取り込み、`#AVI` / `#BMP` の編集(曲パックの BGA の動画は
  流さない。§9.3 は手元のプレー動画を並べるだけ)
- 足した音源・新しい難易度は、ファイル(ZIP・フォルダへの上書き)にするまで、そのページの中と下書きにだけある(新しい難易度は
  下書きから戻せるが、足した音源のファイルは戻らない)
- 999 小節より後ろ(NX は Z99 まで読めるが、本アプリのパーサは 3 桁の 10 進まで)
- 書き直した行の行末のコメントは消える(DTXC も同じ)
